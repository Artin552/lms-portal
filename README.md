# Аудитория — учебный портал (LMS)

Портал для вуза: расписание с чётными и нечётными неделями, домашние задания со сдачей и проверкой, оценки, чаты в реальном времени и уведомления. Роли: студент, преподаватель, администратор.

Название задаётся одной переменной — `APP_NAME` для Docker или `VITE_APP_NAME` для локального запуска.

## Быстрый старт через Docker

```bash
docker compose up --build
```

Откройте http://localhost:8080. При первом запуске бэкенд сам применит миграции и заполнит базу тестовыми данными.

| Роль | Логин | Пароль |
|---|---|---|
| Студент (группа ИСТ-31) | `student` | `student123` |
| Преподаватель | `teacher` | `teacher123` |
| Администратор | `admin` | `admin123` |

Остальные тестовые пользователи: преподаватели `teacher2`, `teacher3` (пароль `teacher123`), студенты `student02` … `student20` (пароль `student123`).

> Секреты в `docker-compose.yml` годятся только для локального запуска. Для реального сервера скопируйте `.env.example` в `.env`, задайте `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `FILE_URL_SECRET` (например, `openssl rand -base64 48`), включите `COOKIE_SECURE=true` и работайте через HTTPS.

## Локальный запуск без Docker

Нужны Node.js 20+ и PostgreSQL 14+. Postgres удобно поднять из того же compose-файла: `docker compose up -d db`. Он заодно создаёт базу `lms_test` для тестов.

```bash
# Бэкенд — http://localhost:4000
cd backend
cp .env.example .env
npm install
npx prisma migrate deploy
npm run seed            # повторный запуск с очисткой базы: npm run seed -- --force
npm run dev

# Фронтенд — http://localhost:5173 (в другом терминале)
cd frontend
cp .env.example .env
npm install
npm run dev
```

Dev-сервер Vite проксирует `/api` и `/socket.io` на бэкенд, поэтому CORS настраивать не нужно.

## Тесты

Интеграционные тесты API (Vitest + Supertest) для авторизации и заданий работают с отдельной базой `lms_test`; миграции к ней применяются автоматически.

```bash
cd backend
npm test
```

Другую тестовую базу можно указать через `TEST_DATABASE_URL`.

## Переменные окружения

**backend/.env**

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL | — |
| `TEST_DATABASE_URL` | База для `npm test` | `postgresql://lms:lms@localhost:5432/lms_test` |
| `PORT` | Порт API | `4000` |
| `CORS_ORIGIN` | Адрес фронтенда (можно несколько через запятую) | `http://localhost:5173` |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | Подпись токенов. В продакшене обязательны | dev-значения |
| `JWT_ACCESS_TTL` | Время жизни access-токена | `15m` |
| `JWT_REFRESH_TTL_DAYS` | Время жизни refresh-токена, дней | `30` |
| `FILE_URL_SECRET` | Подпись временных ссылок на файлы. В продакшене обязателен | dev-значение |
| `FILE_URL_TTL_SEC` | Сколько живёт ссылка на файл, секунд | `3600` |
| `COOKIE_SECURE` | Отдавать refresh-cookie только по HTTPS | `false` |
| `UPLOAD_DIR` | Папка для загруженных файлов | `uploads` |
| `MAX_UPLOAD_MB` | Максимальный размер одного файла | `20` |
| `SEMESTER_START` | Дата начала семестра: от неё считается номер и чётность недели (1-я неделя — нечётная) | `2026-09-01` |

**frontend/.env**: `VITE_APP_NAME` — название портала, `VITE_API_PROXY` — адрес бэкенда для dev-прокси.

## Как это устроено

**Авторизация.** Access-токен (JWT, 15 минут) хранится только в памяти браузера. Refresh-токен лежит в httpOnly-cookie, а в базе — только его SHA-256-хеш. При каждом обновлении токен ротируется. Если кто-то предъявит давно отозванный токен, это расценивается как кража, и отзываются все сессии пользователя. Пароли хешируются bcrypt, попытки входа ограничены по частоте. Права проверяются на каждом маршруте бэкенда. Защита страниц на фронтенде нужна только для удобства интерфейса и безопасность не обеспечивает.

**Расписание.** Номер недели считается от `SEMESTER_START`, а у каждой пары есть признак «каждую неделю / чётная / нечётная». Администратор редактирует расписание формой или загружает CSV. Импорт атомарный: при ошибке в любой строке ничего не записывается, а в ответе — номера строк с ошибками. Шаблон CSV можно скачать в админке.

**Задания.** Преподаватель может выдавать задания только тем группам, у которых ведёт этот предмет (назначения задаёт администратор). Статусы для студента: не сдано, сдано, на доработке, проверено, просрочено. Пересдать работу можно до дедлайна, пока она не проверена. Работу, возвращённую на доработку, можно сдать и после дедлайна. Раз в 10 минут фоновая задача напоминает о дедлайне в ближайшие 24 часа тем, кто ещё не сдал. Каждое напоминание отправляется один раз.

**Чаты.** Общий чат группы и чаты по предметам создаются автоматически и сами синхронизируют состав участников при изменении группы или назначений. Личные диалоги создаются по требованию. Сообщения отправляются через REST (так проще передавать файлы), а рассылаются через Socket.IO. «Прочитано» считается по времени последнего прочтения у каждого участника. Преподаватель в групповых чатах может закреплять и удалять сообщения. Уведомление в колокольчик приходит только о личных сообщениях: по групповым чатам хватает счётчика непрочитанных.

**Файлы.** Разрешены только расширения из белого списка. Файлы скачиваются по временным подписанным ссылкам (аналог presigned URL в S3), которые выдаются только тем, у кого есть доступ к заданию, сдаче или чату. Всё, кроме картинок, отдаётся на скачивание как `application/octet-stream`. Чтобы перейти на S3, достаточно реализовать интерфейс `FileStorage` в `backend/src/storage/storage.ts`.
